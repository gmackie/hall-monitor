  5. Visible correction revisions. Each new committed delivery increments the relevant bucket revision in the same transaction as the counters and dedupe row; a late new delivery revises its original bucket, while an exact duplicate changes no bucket revision. Expose revision and recent/provisional state through internal store reads for W9. Match dimensions for numerator and denominator. A stale/future/refused/conflicting request never changes counters or their revision.
  6. Retention and revocation. Use the single aggregate alarm for the earliest of all dataset expiries; re-arm on restart. Exclude expired records from internal reads even before an alarm fires. Make shortening/changing/revoking a server policy take effect deterministically without extending storage accidentally. Keep dedupe state through the accepted horizon even when a rollup expires; alternatively refuse any occurrence whose permitted historical bucket has expired. Prove an old re-signed event cannot recreate expired totals. Round deletion timestamps to an appropriate coarse boundary where needed so expiry does not reveal sub-bucket event time. Purge tenant data on an explicit authorized revocation path where required, keeping any necessary bounded tombstone/rejection state rather than permitting replay. Do not silently use tenant re-enrollment to reset the no-recount boundary.
  7. Producer gap/outbox retention. Replace the provisional gap-retention behavior for new v2 enrollment with explicit server policy admission. Keep result/receipt/outbox-or-gap completion atomic, preserve the moderation result and existing record cleanup, and avoid any network request on the evaluation response path.
