Overview

Hall Monitor already classifies with Cloudflare's Clef decision models (@cf/cloudflare/clef-flash, escalating once to @cf/cloudflare/clef). This plan adds the second Cloudflare-built family, Clairic, as a typed extraction evaluator. It also gives Hall Monitor its own admin app for policies, models, labels and an evaluation explorer, and exposes a retained, content-free evaluation read API that PlayTrek and EducateOS can render. The first slice is the read API, because product UIs can build against it while the model and admin work continue.

"claire" is Clairic. Cloudflare's Workers AI catalog has no model named "claire". The owner confirmed it means Clairic, a Cloudflare-built extraction model in preview:
  • @cf/cloudflare/clairic: preview since 2026-10-19. $0.10 per M input tokens until 2026-12-01, then $0.24.
  • @cf/cloudflare/clairic-flash: early research preview. $0.10 per M input tokens.
For both models, output tokens are free and the context window is 65,536 tokens. Each answer comes back as a typed field with value, confidence, p_null and source spans. Every text field is a separate pass that bills the whole input again. Judge and rubric scoring stays with Clef's choice and score questions.

Goals & Non-goals

Goals

  • Products can list and fetch their tenant's past evaluations. Each record has the decision, findings, reason codes, models and escalation path, and the receipt and cost. It holds no content.
  • Clairic runs as a second evaluator family behind a per-profile flag. It is priced in a new dated price book and calibrated and gated like Clef.
  • A separate admin app manages:
    • policy profiles and revisions
    • per-profile model routing
    • label review and calibration sets
    • an evaluation explorer
  • A 0.5.0 contracts and client release, with a complete list of breaking changes from 0.2.0 for PlayTrek.

Non-goals

  • Storing or showing raw learner content anywhere in the evaluation path.
  • Letting admins weaken built-in student floors. Overlays stay tighten-only, enforced in the evaluation Worker.
  • Production deploys or npm publishing without the owner's sign-off. Beta and dev deploys are fine.
  • Product UI work. That belongs to the PlayTrek and EducateOS threads.

1 · How Clairic fits next to Clef

A new evaluator family, not a Clef tier. Clef estimates how likely a category is. Clairic extracts typed facts and says where in the text they are. Hall Monitor uses Clairic where extraction helps evaluation and review:

Evidence spans for reviewers and evaluators to citeall text kindslist of personal identifiers (name, handle, address, phone, school), plus a list of quoted unsafe requestsA privacy.* finding with span, and Finding.evidence[] (field, span, confidence). Never the text.

Routing and escalation

  • PolicyProfile.routing is optional, part of the profile revision, and defaults to Clef-only, which is today's behavior: { clef: { enabled, mode, primary, escalation, kinds }, clairic: { enabled, mode, primary, escalation, kinds } }.
  • The per-profile flag is routing.clairic.enabled. Its mode defaults to shadow. Shadow-family findings are recorded in route.classifiers[].shadowFindings and never reach the resolver.
  • Clairic starts with flash and escalates once to clairic when any field's confidence falls in the calibrated ambiguous band, or p_null is above it. Every call first passes authorizeModel (governance).
  • Families run in parallel. Clairic never replaces Clef, and overlays may enable it but never disable Clef where a floor requires Clef.

Calibration, pricing, gates

  • Calibration. Generalize CalibrationSelection into rows keyed by provider, model, family, cohort and decision. The harness accepts any pack pin and family. The Worker loads calibration from the active config release for both families, which finally retires UNCALIBRATED_THRESHOLDS for calibrated cohorts.
  • Pricing. A new book, packages/costing/src/cloudflare-2026-11-22.ts. It carries the Clef rates forward and adds:
    • clairic: $0.10 per M input tokens, effective until 2026-12-01, then $0.24
    • clairic-flash: $0.10 per M input tokens
    Each provider pass is its own UsageAttempt. cloudflare-2026-10-20.ts is not edited.
  • Gates, data-driven and checked by pnpm model-gate, all required before mode: enforce:
    1. Registry status ga, or a recorded owner waiver.
    2. Held-out calibration with at least 2 reviewers plus an adjudicator. Per-cohort precision lower bound at or above 0.80 and FPR upper bound at or below 0.05 (Wilson 95%).
    3. shadow-report diff --model-variant shows no support regression.
    4. Added cost of $0.15 or less per 1,000 evaluations and p95 latency of 800 ms or less.
    5. A governance enrollment lists the model.
    6. evaluator-acceptance passes.

2 · Hall Monitor admin app

  • Hosting. A new apps/admin: one Worker serving a static SPA and /admin/v1/* on its own hostname. The evaluation Worker gets no UI, following the design docs.
  • Auth. Cloudflare Access SSO. The Worker verifies Cf-Access-Jwt-Assertion against the team JWKS. Roles are stored in D1: viewer, policy-editor, labeler, adjudicator, publisher, admin. Two-person rule: whoever publishes a student-facing revision or enables enforce mode must not be its author. Every mutation is written to audit_log.
  • Storage. D1 hm-control holds profile revisions, routing, models, label sets and items, labels, adjudications, calibration studies and rows, releases, and the audit log. Every query is tenant-scoped in code.
  • Config delivery. Publishing writes an immutable, digest-pinned config release (profiles, overlays, routing, calibration, pack pins). The evaluation Worker reads the active pointer, verifies the digest, caches it, and still clamps every overlay to the floors. Secret JSON remains the fallback and break-glass path. HM_GOVERNANCE stays a secret.
  • Evaluation explorer. The admin Worker reaches tenant records through a WorkerEntrypoint RPC class on the evaluation Worker. It is reachable only through a service binding, never from the public hostname, and returns the same content-free EvaluationRecord products get.

3 · Evaluation read API for product UIs (contracts 0.5.0)

Everything here is additive within wire schema 1.0. Records are written in the same transaction as the result and receipt, and are scoped to the token's tenant. They are kept for HM_EVALUATION_RETENTION_SECONDS: 30 days by default, at most 400. Each record is content-free, holding identifiers, labels, codes, spans and counters only.

GET /v1/evaluations/{evaluationId}evaluations:readEvaluationRecord, or 404 if the evaluation is unknown, expired, or belongs to another tenant
GET /v1/evaluations?…evaluations:readEvaluationPage, newest first, with a cursor

POST /v1/evaluations:governedevaluate + hm_governanceUnchanged. The client gains evaluateGoverned.

// New on EvaluationResult (optional)
route?: EvaluationRoute

EvaluationRoute = {
  classifiers: ClassifierRoute[]              // ≤ 8, one per model family
}
ClassifierRoute = {
  family: string                              // "clef" | "clairic" (machine code)
  evaluatorId: string
  evaluatorVersion: string
  status: "ran" | "skipped"
  skipReason?: "moderation_off" | "deterministic_decisive" | "digest_content"
             | "image_moderation_disabled" | "not_configured" | "budget_exhausted"
             | "not_authorized" | "kind_not_routed" | "profile_disabled"
  mode: "enforce" | "shadow"                  // shadow ⇒ findings never reach the decision
  calibrationRevision: string | null          // null = uncalibrated thresholds
  calls: ModelCall[]                          // in order; ≤ 16
  escalated: boolean
  escalationReason?: "ambiguous_band" | "low_confidence"
  fellBack?: boolean                          // escalation failed → primary result kept, uncertain
  shadowFindings?: Finding[]                  // only when mode = "shadow"; ≤ 64
}
ModelCall = {
  modelId: string                             // e.g. "@cf/cloudflare/clef-flash"
  role: "primary" | "escalation"
  outcome: "scored" | "malformed" | "failed" | "timed_out" | "denied"
  attemptId?: string                          // → receipt.attempts[].attemptId (absent when denied, unbilled)
}

// New on Finding (optional)
evidence?: Evidence[]                         // ≤ 16
Evidence = { field: string /* machine code */, span?: Span, confidence?: number /* 0..1 */ }

EvaluationRecord = {
  schemaVersion: "1.0"
  evaluationId: string
  requestId: string
  tenantId: string
  product: Product
  surface: string
  evaluationKind: EvaluationKind
  contentType: "text" | "digest" | "image"
  policy: { profileId: string, revision: string }
  context: { audience, gradeBand?, subject?, activityKind?, graded?, costCenterId, parentRequestId? }

Open Questions

Gate thresholds and budget: the precision lower bound of 0.80 or more, the FPR upper bound of 0.05 or less, and the Clairic budget of $0.15 per 1,000 evaluations and 800 ms p95 are proposals. The owner sets the final numbers.
Record retention: the default is 30 days per deployment. Per-tenant retention can come later through config releases if districts require it.
