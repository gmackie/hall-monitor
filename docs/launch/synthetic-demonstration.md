# Four-case synthetic demonstration (HM-27 / W11)

Run `pnpm synthetic-demo --out dist/demo` and open `dist/demo/index.html` as a local file. The
accompanying `report.json` records eight fictional evaluations and two failure/support checks.
It makes no network calls, contains no scripts or external resources and submits no messages
or reports. The same inputs and fixed clock generate deterministic results.

The demonstration uses the real evaluation core, deterministic bundle, policy resolver and
Clef request/response parser with **scripted model scores**. It is not measured classifier
accuracy, human calibration, a connected product UI, Flightdeck integration or an operational
safeguarding service. Receipts from scripted calls have unknown usage/cost, never measured cost.

| Fictional pair | Implemented mechanism | Live/proposed part |
| --- | --- | --- |
| Quotation versus threat | Core policy and severity resolution | Context-sensitive model answers are scripted |
| Rumor versus supportive reporting | Distinct fictional scores; help remains reachable | Source speech-act handling and trusted reporting integration |
| Personal mute versus required-group removal | Signed action contracts exclude preference events; synthetic causal model | Source-owned committed permission/outbox integration |
| Bait and copied reports | Synthetic evidence grouping, provenance and counterevidence | Intent assessment and trained human review |

The draft model preserves text on unavailable/held outcomes, requires an explicit choice after
an allow, and binds screening to the exact request ID. Editing requires a new ID, invalidating
the previous result. Report/help remain available without the classifier. Those are local flow
tests; the eventual source composer must enforce its own permissions, idempotency, race control,
accessibility and actual publishing boundary. Declining a nudge is not a misconduct signal.

Each card identifies implemented mechanics and proposed source behavior. Its choices are
illustrations, not buttons wired to nonexistent recipients. The Flightdeck sample shows only
eight fictional evaluations; collection coverage and candidate rates remain unavailable. It
does not fabricate cases, reporting totals, verified zeros or response-time metrics.

No source original, student ID or draft enters telemetry. A future real report requires a
verified source/custodian, permitted surface, eligibility, rights/retention and staffed recipient.
An ordinary classroom report is not a confidential safeguarding case channel. Current custody,
pilot host, privacy/legal/model calibration and staffing decisions remain pending.

## Operational evidence still required

The existing Worker/DO rollback drill proves classifier outage handling, policy revision rollback
and replay after object restart locally. Producer/receiver suites cover retry, lost ack, conflict,
retention and revocation using synthetic fixtures. These do not substitute for target-account
deployment/disable evidence, independent source coverage or a staffed Friday-night referral.

Before any live exercise, record actual owners/hours, Friday-night urgent fallback, unavailable
reviewer behavior, source and collector outages, provider approval drift, access revocation,
school withdrawal and deletion/hold handling in the signed launch record. A human must verify
the referral and rights workflows. Software evidence cannot supply those signatures.
